## 2. 시스템 아키텍처

### 2.1 핵심 설계 패턴

**의존성 주입 (DI)**
- 수동 DI 컨테이너로 의존성 관리
- 글로벌 + 씬별 계층적 컨테이너 구조
- `[DIInject]` 속성 기반 필드 주입

**이벤트 버스 (EventBus)**
- 타입-안전한 제네릭 이벤트 시스템
- 모듈 간 느슨한 결합
- UnityEngine 의존성 없는 순수 C# 구현

**MVP 패턴**
- View: Unity UI 컴포넌트
- Presenter: 비즈니스 로직
- Flow Router: 화면 네비게이션 추상화

### 2.2 모듈 구조

```
Core (애그리게이션 계층)
├── Combat (전투 시스템)
├── UIFlow (UI 흐름)
├── Meta (메타 게임)
└── GameData (데이터 관리)

Base Layer
├── DI (의존성 주입)
└── EventBus (이벤트 시스템)
```

## 3. 데이터 파이프라인

### 3.1 Excel 기반 데이터 관리

| 단계 | 도구/방식 | 출력 |
|------|----------|------|
| 기획 | Excel | .xlsx 파일 |
| 임포트 | 커스텀 에디터 툴 | ScriptableObject |
| 런타임 | Addressables | 메모리 로드 |

### 3.2 데이터 종류
- **Floor/Wave:** 스테이지 구성 데이터
- **Enemy:** 적 스펙, 패턴 데이터
- **Weapon:** 무기 스탯, 효과 데이터
- **Reward:** 보상 테이블 데이터

## 4. 핵심 기능

### 4.1 Combat System
- 실시간 전투 루프 (BattleLoopController)
- 적 스폰 시스템 (WaveSpawnPlanner)
- 상태 머신 기반 플레이어/적 행동 관리

### 4.2 Equipment System
- 장비 강화 및 재련
- 랜덤 스탯 롤링
- 장비 비교 및 장착

### 4.3 Progression
- 층별 진행 시스템
- 보상 분배 로직
- 영구 강화 (Growth)

## 5. 품질 관리

### 5.1 테스트 전략

| 테스트 유형 | 범위 | 도구 |
|------------|------|------|
| 단위 테스트 | 각 모듈 로직 | Unity Test Framework |
| 통합 테스트 | 화면 간 흐름 | EditMode 테스트 |
| 전체 테스트 | 플레이through | 수동 QA |

### 5.2 테스트 커버리지
- DI 컨테이너: 컨테이너 계층, 생명주기 관리
- EventBus: 구독/발행, 메모리 누수 방지
- Combat: 배틀 루프, 적 스폰, 상태 전이
- Meta: 장비 로직, 보상 계산
- Core: 화면 전환 통합 테스트

| 영역 | 방식 | 효과 |
