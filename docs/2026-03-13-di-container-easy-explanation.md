# DIContainer 쉬운 설명

## 한 줄 설명

`DIContainer`는 게임에 필요한 물건들을 넣어두었다가, 필요할 때 꺼내 주는 "똑똑한 상자"입니다.

예를 들어 게임 안에는 이런 것들이 있을 수 있습니다.

- 사운드를 재생하는 관리자
- 점수를 관리하는 관리자
- 데이터를 저장하는 관리자

이런 것들을 매번 새로 만들지 않고, 한 곳에 보관해 두었다가 필요할 때 가져다 쓰게 도와주는 것이 `DIContainer`입니다.

---

## 쉽게 비유하면

`DIContainer`는 장난감 정리 상자와 비슷합니다.

- 장난감을 상자에 넣어 둡니다.
- 장난감마다 이름표를 붙일 수 있습니다.
- 나중에 "자동차 장난감 줘"라고 하면 상자에서 찾아 꺼내 줍니다.
- 내가 직접 찾지 않아도, 필요한 자리에 자동으로 넣어줄 수도 있습니다.

즉, 이 코드는 "보관", "찾기", "자동 넣기"를 해 주는 역할입니다.

---

## 코드에서 하는 일

### 1. `Register(...)`

이 함수는 상자 안에 물건을 넣는 기능입니다.

예를 들어:

```csharp
container.Register(soundManager);
```

이 뜻은:

"이 상자 안에 `soundManager`를 넣어 둘게. 나중에 필요하면 꺼내 써."

키(`key`)도 같이 줄 수 있어서, 같은 종류의 물건을 여러 개 구분할 수도 있습니다.

예를 들어:

```csharp
container.Register(bgmPlayer, "bgm");
container.Register(effectPlayer, "effect");
```

그러면 둘 다 사운드 관련 객체여도 이름표로 구분할 수 있습니다.

---

### 2. `Resolve(...)`

이 함수는 상자에서 물건을 꺼내는 기능입니다.

예를 들어:

```csharp
var soundManager = container.Resolve<SoundManager>();
```

이 뜻은:

"상자 안에 있는 `SoundManager`를 꺼내 줘."

그런데 상자 안에 없으면 에러가 납니다.

즉:

- 있으면 준다
- 없으면 "그런 물건 없어요" 하고 멈춘다

---

### 3. `TryResolve(...)`

이 함수도 물건을 꺼내려고 시도하지만, 조금 더 부드럽습니다.

예를 들어:

```csharp
if (container.TryResolve<SoundManager>(out var soundManager))
{
    // 찾았을 때 사용
}
```

이 뜻은:

- 있으면 `true`를 주고 물건도 꺼내 준다
- 없으면 `false`를 주고 조용히 끝난다

그래서 게임이 갑자기 에러로 멈추는 일을 줄이는 데 도움이 됩니다.

---

### 4. `AddContainer(...)` / `RemoveContainer(...)`

이 코드는 상자를 여러 개 등록할 수 있게 해 줍니다.

왜 여러 개가 필요할까요?

- 게임 전체에서 항상 쓰는 공용 상자 1개
- 어떤 특정 씬에서만 쓰는 상자 1개

이렇게 나눠 둘 수 있기 때문입니다.

`AddContainer(...)`는 상자를 등록하고,
`RemoveContainer(...)`는 상자를 목록에서 빼는 역할을 합니다.

---

### 5. `ResolveFromRegistered(...)`

이 함수는 등록된 여러 상자들 중에서 필요한 물건을 찾아줍니다.

중요한 점은 **가장 나중에 등록한 상자부터 찾는다**는 것입니다.

이건 왜 좋을까요?

예를 들어:

- 전체 게임용 상자에 기본 설정이 들어 있음
- 현재 씬용 상자에 더 특별한 설정이 들어 있음

그럼 현재 씬용 상자를 먼저 보는 것이 더 자연스럽습니다.

즉, 더 가까운 곳에 있는 설정이 우선으로 사용됩니다.

---

### 6. `Inject(object target)`

이 부분이 가장 "자동화"에 가까운 기능입니다.

어떤 클래스 안에 `[DIInject]` 표시가 붙은 변수나 속성이 있으면,
`DIContainer`가 알아서 맞는 객체를 찾아 넣어 줍니다.

예를 들어 이런 느낌입니다.

```csharp
[DIInject]
private SoundManager soundManager;
```

그리고 나서:

```csharp
DIContainer.Inject(this);
```

를 호출하면,

"아, 이 칸에는 `SoundManager`가 필요하구나. 내가 등록된 상자에서 찾아서 넣어 줄게."

하고 자동으로 넣어 줍니다.

사람이 일일이 직접 연결하지 않아도 되어서 편리합니다.

---

## 코드 안의 작은 장치들

### `RegistrationKey`

이 구조체는 "어떤 타입인지"와 "어떤 이름표인지"를 같이 묶어 둡니다.

예를 들어:

- `SoundManager` + `bgm`
- `SoundManager` + `effect`

이 둘은 타입은 같아도 이름표가 다르기 때문에 다른 물건으로 구분할 수 있습니다.

즉, `RegistrationKey`는 상자 안 물건의 정확한 이름표 역할을 합니다.

---

## 왜 이런 코드가 좋을까?

이 코드를 쓰면 좋은 점은 다음과 같습니다.

- 필요한 객체를 한 곳에서 관리할 수 있습니다.
- 다른 코드가 직접 새 객체를 만들지 않아도 됩니다.
- 코드를 바꾸거나 테스트하기 쉬워집니다.
- 서로 너무 강하게 연결되지 않아서 관리가 편해집니다.

쉽게 말해,
각 코드가 "내가 다 알아서 만들게" 하지 않고,
"필요한 건 공용 상자에서 받아 쓸게"라고 하는 방식입니다.

그래서 더 깔끔한 구조를 만들 수 있습니다.

---

## 정말 짧게 다시 정리

`DIContainer`는:

- 객체를 저장해 두고
- 필요할 때 찾아 주고
- 여러 상자 중에서 적절한 것을 골라 주고
- `[DIInject]` 표시가 있으면 자동으로 넣어주는

도구입니다.

한마디로,
**게임 안의 필요한 물건들을 관리해 주는 똑똑한 보관함**이라고 생각하면 됩니다.
